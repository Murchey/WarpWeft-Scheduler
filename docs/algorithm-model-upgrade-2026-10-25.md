# 排课算法与模型改进记录（2026-10-25）

> 依据：`D:\测试数据\排课测试数据\排课差距与算法缺陷-2026-10-25.md`  
> 目标：把报告指出的「固定时间、连堂、单双周同格、学科时段结构、教师可用时间、模板可用性」缺陷落到代码里，而不是只改数据。

## 1. 结论

本次把报告第六节的 1–5、7、11 项落到了模型、求解器、导入模板和界面：

| 报告缺陷 | 本次处理 |
| --- | --- |
| 1. 固定时间只能挂在整条计划上 | 新增 `fixedSlotIds`（课次级固定列表）；计划可只固定其中几节 |
| 2. 固定时间不是强保护 | 求解器先占固定时段、预留时段、禁止弹出固定课；修复时优先补固定课 |
| 3. 语数间周没有原生模型 | 新增 `pairId`：同一配对组的单/双周计划必须同一时间格，求解器整组放置 |
| 4. 缺少连堂/双节 | 计划新增 `consecutive`（2–4 节），按整段相邻节次放置；固定时段本身相邻时自然形成锚定连堂 |
| 5. 缺少主科上午 / 副科下午结构 | 学科新增 `preference`（上午/下午），求解器新增 `SUBJECT_TIME_PREFERENCE` 软目标；导入时给可修改的推荐值 |
| 6. 教师可用时间没进模板 | 导入模板新增「教师时间」工作表，批量导入教师不可用时段 |
| 7. 自动分配教师依据太弱 | 增加周课时/每日上限/可用时段过滤，并优先复用已在班任课的教师 |
| 11. 模板本身的问题 | 去掉「时间段」重复示例行；真实 7 节/天导出 7 行；新增固定/连堂/配对/偏好/教师时间列与表 |

数据版本从 3 升到 4，新增能力标记：`fixedSlotLists`、`consecutiveRuns`、`weekPairing`、`subjectTimePreference`、`teacherAvailabilityImport`。

## 2. 模型改动

### 2.1 教学计划（`CoursePlan` / Java `Plan`）

```ts
interface CoursePlan {
  // ...原有字段
  fixedSlotId?: string;    // 旧字段，继续兼容
  fixedSlotIds?: string[]; // 新：第 i 节课固定到 fixedSlotIds[i]
  consecutive?: number;    // 2–4：连续几节一起排
  pairId?: string;         // 同一配对组必须共用同一时间格（单/双周）
}
```

兼容规则：`fixedSlotIds` 优先；没有列表时回退到旧的 `fixedSlotId`。固定数量不能超过周课时，列表内不能重复。

### 2.2 学科（`Subject`）

```ts
interface Subject { id: string; name: string; preference?: 'morning' | 'afternoon'; }
```

上午/下午以当天实际节次的中间值为界（7 节/天 → 1–4 节为上午）。未设置偏好的学科不参与该软目标。

### 2.3 软目标

新增 `SUBJECT_TIME_PREFERENCE`，默认权重 2（0 = 关闭）。求解器在构造选位和最终评分里同时使用：

- 语文/数学等「上午」学科排到下午扣分；
- 阅读/班会/作文等「下午」学科排到上午扣分；
- 权重只影响位置，不影响可行性。

## 3. 求解器改动

### 3.1 固定时段硬保护

- 开始时为「尚未落位的固定节次」预留班级+教师时段（按单/双周掩码）。
- 固定课在所有可移动课程之前放置；失败时保留预留，后续自由课不能占用。
- 固定节次通过弹出修复放置时，只允许在它自己的固定时段内找位置，且自身预留先释放、失败再恢复。
- 被固定的课、走班课、锁定课、配对课不会被弹出；随机重启（ruin-and-recreate）也不会踢掉这些课。

### 3.2 连堂

- 计划级 `consecutive` 与原有 `DOUBLE_PERIOD` 规则合并，取较大值（上限 4）。
- 连堂计划先按「整段相邻节次」成组放置，剩余奇数节再单排。
- 固定时段相邻（如周四第 6、7 节）时直接形成锚定连堂，不再依赖软约束。

### 3.3 单双周同格

- `pairId` 相同的计划作为一组，一次性放在同一时间格：
  - 先试「不弹出」的所有时段；
  - 找不到再逐段弹出 1–2 个阻挡课并整体回滚/提交；
  - 整组一起放置，避免「先放 A 占了 B 的教师/教室」。
- 自由配对优先落在一个共同锚点时段（选能容纳最多配对组的时段），贴近学校「语数间周固定周五第 7 节」的惯例；锚点放不下的组在其余空档补排。
- 导入、界面检查、服务端保存都校验：同班配对组成员周次不能重叠，固定时间必须一致。

### 3.4 选位与评分

- 固定课优先；其次走班；再连堂；再普通课；最后补放不下的自由配对。
- 选位评分增加学科时段偏好项；`scoreBreakdown` 新增 `subjectTimePreference`。

## 4. 导入模板与界面

### 4.1 教学计划新增列

| 列 | 示例 | 说明 |
| --- | --- | --- |
| 固定时间 | `周一 第5节；周四 第6节` | 多个用 `；` 分隔，按顺序固定第 1、2…节 |
| 连堂节数 | `2` | 2–4；留空不连堂 |
| 配对组 | `语数间周` | 单周/双周两条计划填同一个值 |

### 4.2 学科新增列

`时间偏好`：上午 / 下午 / 不限。留空时按学科名给出推荐值（可通过填空「不限」明确不限制）。

### 4.3 新增「教师时间」工作表

| 教师 | 星期 | 节次 |
| --- | --- | --- |
| 王老师 | 周一 | 1;2 |

导入后整体替换「教师不可用时间」。排课会自动避开。

### 4.4 界面

- 教学计划表 / 批量新增：固定时间改为「编辑」弹窗，可多选并显示「第 1、2…节」顺序；新增连堂、配对组输入。
- 学科表：新增时间偏好下拉。
- 课表预览：固定节次不能单独移动；配对课程不能单独交换。
- 课表检测：新增「固定时间」（多节）、「连堂」两类检查。

### 4.5 模板修复

- 删除「时间段」表头下的重复示例行（旧版第 1 节示例会覆盖真实第 1 节）。
- 只有空白模板默认 8 节；真实 7 节/天的数据导出 7 行。
- 旧模板的示例行仍能识别并跳过（即使缺少新增列），避免把「示例学科」导入成真实学科。

## 5. 实测（工作区 45 班 / 690 条计划 / 1620 条两周任务）

测试数据：`data/warpweft.json`（45 班、149 教师、16 学科、35 个时段/周、690 条计划）。  
运行方式：`resources/solver/warpweft-solver.jar`，`randomSeed=1`；除特别说明外使用工作区原有软约束。

### 5.1 报告中的失败场景：45 个班会固定周一第 5 节

| 指标 | 旧求解器（报告） | 本次 |
| --- | --- | --- |
| 20 秒 | 1616/1620，FAILED | — |
| 60 秒 | 1619/1620，FAILED | — |
| 30 秒 | — | **COMPLETED，1620/1620，8.6 秒** |
| 45 节班会位置 | 被挤出 | **45/45 全在周一第 5 节** |

### 5.2 报告建议的完整结构

结构：班会健康固定周一第 5 节；书香阅读固定周五第 5 节；数学益智固定周五第 6 节；作文固定周四第 6+7 节并连堂 2；单周语文 + 双周数学按班配成 `pairId`；学科时段偏好开启；教师每日上限 4 节（必须）。

| 指标 | 原始模型（工作区软约束） | 改进模型 |
| --- | ---: | ---: |
| 状态 | COMPLETED | **COMPLETED** |
| 两周任务 | 1620/1620 | **1620/1620** |
| 耗时 | 约 18.3 秒 | **约 8.6 秒** |
| 固定节次 | — | **195/195 节（165 个计划）全部在指定时段** |
| 配对组 | — | **45/45 组同格** |
| 语文上午占比 | 65.5% | **99.4%** |
| 数学上午占比 | 58.1% | **98.8%** |
| 书香阅读上午占比 | 68.9% | **4.7%** |
| 班会健康上午占比 | 44.4% | **0%** |
| 教师单日最大 | 5 | **4** |

## 9. 仍需确认或后续处理

1. **协同教学/多教师**：一条计划仍只能有一个教师；报告 2.6 班科学的重复教师、走班/协同教学需要新的计划-教师多对多模型。
2. **班级固定教室**：求解器仍按容量/类型选教室；若学校要求「本班只用本班教室」，需要把班级-教室绑定加进硬约束。
3. **班主任数据**：班级表班主任仍为空；导入后「班主任在本班至少一节课」无法自动成立，需要学校补数据。
4. **教师时间来源**：模板已支持导入，但来源 59 张教师课表需要整理成「教师/星期/节次」行；本次没有从教师课表自动反推不可用时间。
5. **配对 + 连堂同时使用**：配对计划会跳过连堂成组（避免语义冲突）；如确实需要「单双周各两节连堂」，需要扩展配对组的 lesson 模型。
6. **启发式边界**：整校满格 + 大量硬锚点时，求解器可能用满时限；结果仍是「找到可行解」而非最优性证明，长时任务可用更长时间继续优化软目标。
