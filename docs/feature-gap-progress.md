## 1. 求解器增强（对应清单第 5 项、P0-1）

**改了什么**（`services/solver-java/.../engine/`）

1. **增量负载计数**：`State` 维护班级/教师/学科按天的课时数和教师按天的节次集合，`add/remove` 增量更新。构造时每次候选检查从「遍历全部课表条目」变成 O(1)，大课时下构造速度提高两个数量级。
2. **最受限优先排序**：`Scheduler.pressureOf()` 按「可用教室数 × 可用时段数」倒数 + 教师/班级负载估算压力，压力大的计划先排；每次重启加 0.05 的随机抖动，避免每次重复同一组失败。
3. **弹出修复（ejection repair）**：构造完成后，对每个未排课时，先直接找位置；找不到就尝试「挪走 1–2 个挡路条目 → 放下当前课 → 再把被挪条目安排到别处」，失败回滚（`State.snapshot/restore`）。固定时间课程只在固定时段内做弹出，绝不移到别的时段。
4. **热启动 / ruin-and-recreate**：机会用完仍未排满时，以当前最优解为底，随机踢掉 5% 课程后调用修复；只有「未排更少」或「未排相同但评分更高」才替换最优解，保证最佳解单调不降。
5. **随机化选位**：非固定课程按随机顺序遍历时段，评分仍按班级/教师/学科负载与规则惩罚，等价于随机重启时探索不同起点。
6. **候选教室缓存**：按计划预筛「类型匹配 + 容量足够」的教室，避免每次全量遍历教室。

**证据**（`node scripts/bench-solver.cjs`，每次 30 秒时限，合成数据、每班一间教室、无规则）

| 96 班 / 2880 课时 | **1470/2880（30s 用尽）** | **2880/2880（4.2s）** |
| 120 班 / 3600 课时 | 未测（原文档口径排不完） | **3600/3600（6.2s）** |

## 4. 长时任务（对应清单第 5 项「长跑任务」、第 6 项进度，P0-1）

**能力**

1. **任务化**：新增 `POST /api/solve/long`、`GET /api/solve/jobs`、`GET /api/solve/jobs/:id`、`POST /api/solve/jobs/:id/{pause|resume|cancel}`。任务元数据、输入与最佳检查点写入 `data/solve-jobs/`（`<id>.json` + `<id>.best.json`），服务重启后自动恢复为「已中断（可继续）」。
2. **长时模式**：时限 30 分钟 / 1 小时 / 2 小时 / 6 小时，服务端硬上限 6 小时；求解器支持 `stagnationSeconds`，连续无改进自动停止（避免白跑）。
3. **检查点**：Java 每有新最优解就原子写入检查点文件（最多 1.5 秒一次），并输出 `[progress] {placed,total,score,elapsedMs}`；服务端解析进度、前端每 2 秒轮询。
4. **暂停/继续**：暂停杀掉 JVM 但保留检查点；继续时把检查点条目作为 `seedEntries` 交给求解器（条目可再被修复移动），用户手动锁定的条目仍按 `lockedEntries` 保持不动。
5. **独占**：同一时间只允许一个长时任务，第二个请求返回 `409 LONG_JOB_BUSY`；长时任务运行期间会占用一个并发槽（`maxConcurrentJobs=1` 时短任务排队，不再额外起第二个 JVM）。
6. **UI**：排课任务页新增「长时排课任务」面板：进度条、已排/总数/未排/评分/轮次/检查点时间、暂停/继续/取消、「载入最佳课表」；载入时会过滤掉引用了已删除班级/教师/教室/时段的条目。
7. **安全**：普通 `/api/solve` 会剥掉客户端传入的 `checkpointFile`，避免 LAN 客户端让求解器写任意路径。

**测试**

- `tests/long-job.test.cjs`（4 条）：进度与检查点落盘、暂停后继续、重启后恢复并继续、取消与非法请求、同一时间只允许一个长时任务。
- `tests/java-long-solver.test.cjs`（3 条）：检查点与进度行、`seedEntries` 续算、停滞检测让不可解样本从 20 秒提前到 1.3 秒结束。

**截图**：`build/shots/long-run.png`（运行中）、`long-run-completed.png`（完成）、`long-apply-java.png`（载入后候选变 21/21）。

## 5. 单双周排课（对应清单第 2 项，P1）

**模型与求解器**

- `CoursePlan.weeks: 'all' | 'odd' | 'even'`（默认 `all`，兼容旧数据）；`ScheduleEntry.weeks` 由计划派生并随求解结果返回。
- 周次用位掩码表示：每周 = 3（单｜双）、单周 = 1、双周 = 2；两个条目只有掩码相交才算冲突。
- `State` 的班级/教师/教室占用从 `Set` 改为 `Map<key, mask>`；教师/班级/学科按天负载、教师按天节次计数器按周次分桶（3/1/2），查询时只累加与候选周次相交的桶，仍是 O(1)。
- `RuleEvaluator.canPlace` 用周次掩码判断，`must` 规则（教师每日上限、学科每日上限、连续上限）按候选所在周次计数。
- 固定时间、锁定条目、长时任务的续算 `seedEntries`、检查点输出都带周次；同一教师单周/双周同槽可以同时排课。

**前端**

- 课表页新增「全部 / 单周 / 双周」筛选：已排/计划/未排/硬冲突都按该周次统计，卡片显示「单周 / 双周」角标；单周课可以拖到双周课占用的格子（冲突判断按掩码）。
- 教学计划表、批量新增弹窗新增「周次」选择；导入模板「教学计划」表新增「周次」列（每周/单周/双周，空值=每周），导入校验会拒绝无法识别的周次。
- 预检按周次折算班级/教师周课时（单周 + 每周 / 双周 + 每周），固定时间冲突只在周次相交时报错——否则单双周共用固定时段会被误判为冲突、无法进入排课。
- 检测引擎按周次判定重复占用，规则违反按单/双周分别计数，避免把单双周共用时段误报成硬冲突。
- 统计报表新增「折算平均周课时」：单/双周计划按 0.5 权重折算（列仍显示该周次的实际课时）。

**测试**

- `tests/java-weeks.test.cjs`（4）：单双周共用固定时段可解、每周课与单双周冲突、同教师单双周同槽、同周次仍冲突。
- `tests/inspection.test.cjs`：单双周同槽不误报、每周课冲突时三条都标出、同教师单双周不冲突。
- `tests/statistics.test.cjs`：折算平均周课时；`tests/import-export.test.cjs`：模板含「周次」列；`tests/api-validation.test.cjs`：拒绝非法周次。

## 7. 早晚补课时与今日视图（对应清单第 7 项、第 10 项「查看上课情况」，P2）

**模型**

- `TimeSlot.kind: 'morning' | 'regular' | 'evening' | 'makeup'`（默认 `regular`）、`start`（HH:MM）、`duration`（分钟）。
- `CoursePlan.kind`：计划只能排进同类型时段——常规课不会被塞进早读/晚自习（除非把计划声明为早读/晚自习/补课）。
- 求解器 `Slot`/`Plan` 带 `kind`，`RuleEvaluator.canPlace` 先比对类型；早读、晚自习、补课各自只与同类型时段配对。
- 预检新增：计划的时段类型没有对应时间段时直接报错；时间段类型/开始时间由 API 持久化校验。

## 9. 走班排课（对应清单第 9 项，P3，MVP）

**模型**

- `ElectiveGroup { id, name, subjectId, weeklyPeriods, classIds[], blocks[] }`；`ElectiveBlock { id, name, teacherId, roomType? }`，持久化在 `SchoolData.electiveGroups[]`，随 `SolverInput.electiveGroups` 传给求解器。
- 语义：一次走班组课 = 同一时段并行开设多个 block；组内所有行政班在该时段整体让出；block 之间教师与教室不得重复。

**求解器**

- `State` 维护 `groupId → classIds`：走班条目的占用会写入所有成员班的 `classSlot`，因此普通课程不会排进走班时段，两个走班组也不会争同一批班级。
- `placeElectiveGroup` 为每次组课寻找一个时段：所有成员班空闲、每个 block 的教师空闲且不在不可用时间、每个 block 都能分到匹配类型/容量且互不相同的教室；走班组先于普通课程排。
- 同一 block 教师重复、并行班多于可用教室、班级/教师/学科不存在等都会导致无解或明确的 violation；总课时与未排统计包含走班块；检查点与输出带 `groupId/blockId`；ruin-and-recreate 不会移动走班条目。

**界面**

- 排课准备新增「走班组」：组名、学科、每周节数、参与班级多选、并行班（名称/教师/教室类型）增删。
- 课表班级视图把一组并行班显示为一张「走班」卡片（学科 + 并行班数 + 教师名单），该时段不再出现行政班课程；教师/教室视图显示各自负责的 block；走班课程只读，不能拖动或锁定。
- 检测引擎识别走班条目：不误报缺失班级/教学计划，按成员班展开占用、同一组多个 block 只算一次班级占用，班级利用率计入走班课时。
- 统计报表教师表新增「走班课时」列并计入占用率，导出同步；API `validateData` 校验走班组与并行班引用。

**测试**

- `tests/java-electives.test.cjs`（5 条）：两组 × 3 并行班可排、成员班在走班时段让出、重复 block 教师无解、并行班多于教室无解、非法输入报明确 violation。
- `tests/inspection.test.cjs`：走班多 block 只算一次班级占用、成员班有普通课才算冲突。
- `tests/api-validation.test.cjs`：走班组引用校验；`tests/statistics.test.cjs`：走班课时按教师统计。

**验收对照（文档 MVP）**：能定义 2 个走班组、每组 3 个并行班 ✅；求解后组内学生课表不冲突（同组 block 同槽、成员班让出）✅；行政班课表正确让出时段 ✅。

**截图**：`build/shots/electives-editor.png`（走班组编辑器）、`electives-timetable2.png`（班级视图走班卡片 + 0 冲突）、`electives-inspection.png`（检测通过）。

> **未做（超出 MVP）**：学生选课与按学生课表、走班课时进入 `LessonLog`/实际授课、走班条目的手工调整；走班组只支持统一 `weeklyPeriods`，不支持按周次/日期变化。
